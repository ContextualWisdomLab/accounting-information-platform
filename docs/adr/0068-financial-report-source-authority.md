# ADR 0068: Bind financial-report source authority to AIS persistence

- Status: Proposed
- Date: 2026-09-04
- Owners: Accounting Information Platform
- Related: ADR 0001, ADR 0006, ADR 0021, ADR 0037, ADR 0049, ADR 0050, ADR 0051, ADR 0067, Issue #51

## Context

ADR 0067 introduced a deterministic financial-report/XBRL proposal format but deliberately classified caller-supplied statement packages as `proposed`, `unverified`, and non-authoritative. A content hash can prove that bytes did not change; it cannot prove that the amounts, company, book, fiscal period, reporting currency, period state, observation cutoff, or system recording time originated from the Accounting Information Platform.

The next commercial gap is therefore not another renderer. The platform needs a database-owned source registry that can prove which retained AIS snapshot population a later report artifact consumed. That registry must remain narrower than validation, approval, publication, filing, or regulator acceptance so those later responsibilities cannot be smuggled into a persistence identifier.

ADR 0051 already established that fiscal-period close state is accounting-book scoped: statutory and management books sharing one calendar period may close independently. A reporting source that reads only `fiscal_period.period_status_code` would violate that existing domain boundary and could misstate the selected book's close state.

The active reconciliation stack owns unreleased forward migrations beginning at `0015` and currently extends beyond `0020`. This branch therefore uses `0020_financial_report_source_registry.sql` only as a provisional branch-local filename for isolated development and rollback-only PostgreSQL acceptance. It is not an integration-safe migration number. After the reconciliation dependency root integrates into protected `develop`, this reporting slice must be non-force restacked onto that exact protected head, assigned the next then-unclaimed forward migration number, and have installer/tests/docs rebuilt together. Reconciliation migration history must not be rewritten to make room for this slice.

## Decision

Create two normalized records under `accounting_reporting`.

`financial_report_run` records one immutable accounting/reporting scope:

- tenant account;
- legal entity;
- accounting book;
- current fiscal period and optional comparison period;
- composite foreign keys proving both periods belong to the selected accounting book's `accounting_book_period_control` scope;
- reporting currency derived from the referenced accounting book;
- current period status derived from the selected book's `accounting_book_period_control`, never from the tenant-global calendar row;
- database observation cutoff generated by PostgreSQL at run creation;
- database-owned `recorded_at` system time that caller input cannot set or later rewrite;
- caller purpose label retained as request context, not as proof of authority;
- a deliberately narrow lifecycle of `collecting_sources` or `superseded`.

`financial_report_source` records the retained evidence population used by that run:

- current or comparison period role;
- an existing `trial_balance_snapshot` foreign key;
- a fixed `financial_statement_population` source role;
- database-owned `recorded_at` system time for the source-link observation;
- append-only evidence identity.

PostgreSQL enforces that a source snapshot belongs to the same tenant, legal entity, accounting book, expected book-scoped fiscal period, and reporting currency as the report run. A source snapshot generated after the database-owned knowledge cutoff is rejected. Both tables use forced row-level security bound to `accounting_core.current_tenant_account_id()` and revoke public privileges.

The run insert trigger overwrites caller-supplied reporting currency, period status, observation cutoff, system recording time, and initial run status with database-derived values. The source insert trigger independently overwrites caller-supplied `recorded_at` after source-scope validation, and the source row is immutable thereafter. The report-run scope guard includes `recorded_at`, so a privileged writer cannot rewrite system chronology after insertion.

There is intentionally no `source_bound`, `validated`, `approved`, `filing_ready`, or `published` state in this slice. A later owner command must define the transition from collected evidence to a complete report source package and must prove the required source population before any stronger status is introduced.

## Alternatives rejected

### Treat a report proposal hash as source authority

Rejected because a caller can hash an internally consistent package for an entity, currency, period, or snapshot that AIS never recorded.

### Read close state from `fiscal_period`

Rejected because ADR 0051 gives each accounting book its own period-control state. A tenant-global fallback can make a statutory report appear open while that statutory book is hard-closed, or vice versa, when another book shares the same calendar period.

### Accept caller-supplied `recorded_at`

Rejected because `recorded_at` is system chronology. Allowing an importer or privileged caller to backdate a report run or source link would make later provenance, replay, retention, and audit decisions depend on caller claims rather than database observation order.

### Copy all statement facts into the source registry

Rejected because that creates another accounting truth store and duplicates the retained trial-balance population. The registry references authoritative source evidence; derived report facts remain artifacts.

### Add validation, maker-checker, and publication tables now

Rejected because source authority, taxonomy validation, approval, publication, and regulator submission are different bounded responsibilities. Combining them would make a source record appear stronger than the implemented controls justify.

### Reuse reconciliation migrations or tables

Rejected because bank-reconciliation evidence and financial-report source evidence have different domain meaning and lifecycle. The only shared dependency is existing AIS accounting scope and retained snapshot evidence. Migration numbering is reconciled only after the accounting dependency root integrates; no source/table authority is shared.

## Consequences

Positive consequences:

- a later report command can distinguish AIS-retained source evidence from arbitrary caller packages;
- tenant/entity/book/book-period/currency substitution fails at the database boundary;
- statutory and management books retain independent close semantics in financial reporting;
- observation cutoff and recording chronology are not caller-asserted;
- report-source evidence is append-only and independently auditable;
- no new publication or compliance claim is created.

Costs and limitations:

- the provisional `0020` filename must be renumbered to the next unclaimed forward migration after the reconciliation stack integrates, with installer/tests/docs updated on the same restacked head;
- the current trial-balance snapshot remains the retained numerical source, so disclosure completeness and taxonomy mapping are still separate work;
- this slice does not yet create the authenticated application command that assembles and finalizes the complete source set;
- official IFRS/DART profiles, independent XBRL validation, accessible renderers, verified commentary, maker-checker, publication receipts, supersession/withdrawal, and recovery remain in Issue #51.

## Verification requirements

Before this ADR can move beyond Proposed, the exact integrated head must prove:

1. clean PostgreSQL 18 installation using the final non-colliding forward migration number after the reconciliation dependency chain;
2. forced-RLS cross-tenant denial for both new tables;
3. rejection of a current or comparison period that is not controlled by the selected accounting book;
4. the stored period status is the selected accounting book's period-control status;
5. rejection of a snapshot from another entity, book, period, or currency;
6. rejection of a snapshot newer than the database-owned cutoff;
7. caller-supplied currency, period status, cutoff, run `recorded_at`, and initial run status cannot survive insertion;
8. caller-supplied source `recorded_at` cannot survive insertion, and run `recorded_at` cannot be rewritten;
9. source UPDATE/DELETE fails closed;
10. the public migration installer fails closed if the final reporting-source migration is absent or fails;
11. full repository statement and branch coverage remain 100%;
12. current-head security/package gates and independent review pass.

Until those conditions are present on one exact head, the ADR remains Proposed and the PR remains Draft.

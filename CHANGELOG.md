### Added

- `lookup_receivable_aging` and `GET /receivable-agings?legal_entity_reference=&book_reference=&fiscal_period_reference=` return entity-level FIFO receivable aging as of the fiscal period end date. Default `chart_account_code` is the catalog `accounts_receivable` map (110100). Optional `chart_account_code` must be that AR account; an unknown code is 404 and a cash or revenue code is 422. Debit AR lines age from `accounting_date`; credit lines consume the oldest open debit first using exact decimals. Adjusting journals that touch AR are included; the AIS period-closing journal is excluded. After hard-close, aging still reads live journals through period end and `total_outstanding_amount` equals `GET /account-balances` net for that AR account. Empty history is zero buckets, not 404. This slice has no party or customer dimension. `POST /receivable-agings` is 405.
- `GET /journals` period list accepts optional `journal_source_code` (`billing` | `adjusting` | `period_closing` | `reversal`). Omit keeps today's list and omits the envelope key. When supplied, the envelope includes `journal_source_code` and the page is the matching whole journals inferred from existing rows: adjusting lines (`account_role_code=adjusting`), the AIS period-closing URN, `journal_reversal` lineage, or remaining Billing posts. Empty match is `journals` []. Invalid source is 400. Single-journal GET by `idempotency_key` or `journal_reference` is unchanged.
- `lookup_financial_statement_package` and `GET /financial-statement-packages?legal_entity_reference=&book_reference=&fiscal_period_reference=` return the four IAS 1 statements for one book and period (`income_statement`, `balance_sheet`, `changes_in_equity`, `cash_flow`). Each inner document is the exact `GET /financial-statements` result for that type. Optional `statement_scope_code` (`period` | `year_to_date`) and `comparison_fiscal_period_reference` keep today's single-statement meaning; the package includes `statement_scope_code` only for `year_to_date`. Empty books return four zero-amount statements. `GET /financial-statements` is unchanged. `POST /financial-statement-packages` is 405.
- `GET /trial-balances` accepts optional `balance_basis_code` (`unadjusted` | `adjusted` | `post_close`) on the existing route. Omit keeps today's live-or-snapshot document and does not add the key. `unadjusted` is a live as-of sum that excludes `account_role_code=adjusting` lines and the AIS period-closing journal. `adjusted` includes adjusting journals and still excludes that closing journal. Both live bases work on open, `soft_closed`, and `hard_closed` periods and do not read the snapshot. `post_close` returns the stored `trial_balance_snapshot` only; open or soft-closed books without a snapshot are 409. Invalid basis is 400. Empty books stay 200 with `lines` []. `GET /account-balances`, `GET /account-rollforwards`, and `GET /financial-statements` are unchanged.
- `lookup_account_rollforward` and `GET /account-rollforwards?legal_entity_reference=&book_reference=&fiscal_period_reference=&chart_account_code=` return one account working paper: unsigned `opening_*`, `period_*`, and `closing_*` debit and credit sides. `closing_*` is opening plus period on each side and equals `GET /account-balances` for that account and period. Opening uses the prior hard-close snapshot when one exists, otherwise live lines before the scope start. Period activity includes posted adjusting journals and, after hard-close, the AIS period-closing journal on the accounts it touches. Optional `statement_scope_code` (`period` | `year_to_date`) keeps today's omit rule (`statement_scope_code` on the document only for `year_to_date`). Empty activity on a known catalog account returns zeros. `GET /account-balances` is unchanged. `POST /account-rollforwards` is 405.
- `lookup_account_balances` and `GET /account-balances?legal_entity_reference=&book_reference=&fiscal_period_reference=` return as-of chart-account balances for one tenant book and period (`chart_account_code`, `account_class_code`, unsigned `debit_amount` / `credit_amount`). Hard-closed periods read the stored `trial_balance_snapshot` (same source as `GET /trial-balances` and `GET /period-closes`). Open and soft-closed periods sum posted journal lines through period end, including AIS adjusting journals. Optional `chart_account_code` returns that one account in the collection; an unknown code is 404. Default `page_limit` is 50, maximum 100, and `next_cursor` is `chart_account_code`. Empty books return `account_balances` []. `GET /account-ledgers` and `GET /trial-balances` are unchanged. `POST /account-balances` is 405.
- `GET /financial-statements` accepts `statement_type_code=cash_flow` on the existing route. Movement rows are `period_net_income`, `operating_working_capital`, `cash_from_operations`, `cash_from_investing`, `cash_from_financing`, `net_cash_change`, `opening_cash`, and `closing_cash`. The projection is the IAS 7 indirect method. Cash accounts are the current `cash_receipt` mapping (seeded 110200). `period_net_income` reuses the income-statement operational result (closing journals excluded). `operating_working_capital` is the period change in non-cash asset and liability class accounts, signed so an AR increase is a use of cash. `cash_from_financing` reuses changes-in-equity `other_equity_movements`. Investing stays 0 unless a non-cash non-equity asset acquisition already exists in the books; this slice does not invent one. Rows are credit-normal: a cash increase is `credit_amount`, a decrease is `debit_amount`. `closing_cash` equals opening plus net cash change and equals the balance-sheet cash-account total for the same scope. After hard-close, period net income stays the pre-close operational result and the closing journal is not working capital or financing. Optional `statement_scope_code` and `comparison_fiscal_period_reference` keep today's meaning and omitted keys. Empty books return the eight rows at zero. `income_statement`, `balance_sheet`, and `changes_in_equity` are unchanged.
- `GET /financial-statements` accepts `statement_type_code=changes_in_equity` on the existing route. Movement rows are `opening_equity`, `period_net_income`, `other_equity_movements`, and `closing_equity`. `period_net_income` reuses the income-statement operational result (closing journals excluded). `other_equity_movements` are equity-class journals in the scope excluding the AIS period-closing journal. `closing_equity` equals opening + net income + other and equals the balance-sheet equity total for the same scope (equity class plus unparked `net_income_amount` before hard-close; parked RE after). Opening uses the prior hard-close snapshot when one exists, otherwise live equity before the scope start. Optional `statement_scope_code` and `comparison_fiscal_period_reference` keep today's meaning and omitted keys. Empty books return zero amounts. `income_statement` and `balance_sheet` are unchanged.
- `accept_adjusting_journal` and `POST /journals` post one AIS-owned adjusting journal on the existing stdlib HTTP surface and return the existing `accounting_posting_receipt`. Body keys are `tenant_reference`, `legal_entity_reference`, `accounting_book_reference`, `fiscal_period_reference` or `period_code`, `journal_date`, `idempotency_key`, `journal_description`, and `journal_lines` (`chart_account_code`, `debit_credit_code`, `amount`, `currency_code`). Lines use AIS chart codes, not Billing `account_role_code`. The period must be `open` or `soft_closed`; `hard_closed` is 409. Replay of the same tenant plus `idempotency_key` returns the existing receipt. `GET /journals` query keys are unchanged and return the adjusting journal after accept. Billing `POST /journal-proposals` remains Billing ingest.
- `lookup_period_closes` and `GET /period-closes?legal_entity_reference=` list durable hard-close receipts from existing `trial_balance_snapshot` rows using the same close-receipt keys (`tenant_reference`, `legal_entity_reference`, `accounting_book_reference`, `period_code`, `period_status_code`, `snapshot_record_id`, `snapshot_generated_at`, `source_journal_count`, `source_payload_hash`, and `replayed` false). Soft-close writes no snapshot, so GET does not invent soft-close history. Optional `fiscal_period_reference` and `period_status_code` (`soft_closed` | `hard_closed`) filter stored rows. Default `page_limit` is 50, maximum 100, and `next_cursor` is `snapshot_generated_at|snapshot_record_id`. Empty history returns `period_closes` []. `POST /period-closes` remains the close command.
- `lookup_journal_reversals` and `GET /journal-reversals?legal_entity_reference=` list existing `journal_reversal` rows for the bound tenant entity (`reversal_journal_reference`, `original_journal_reference`, `reversal_date` from the reversing journal `accounting_date`, `posted_at`, and stored `reversal_reason_code`). Optional `original_journal_reference` and `fiscal_period_reference` filter those stored rows. Default `page_limit` is 50, maximum 100, and `next_cursor` is `posted_at|journal_reference`. Empty history returns `journal_reversals` []. Unknown original journals return that empty list. Missing legal entity or period is 404. `POST /journal-reversals` remains the reverse command.
- `GET /financial-statements` accepts optional `statement_scope_code` (`period` | `year_to_date`) on the existing route. Omit or `period` keeps today's keys and returns that period's operational P&L (AIS closing journals excluded) or the as-of balance sheet. `year_to_date` income statements sum same-year revenue and expense from the first period through `fiscal_period_reference`; year identity is the `YYYY` prefix of `period_code` or else `period_start_date`. `year_to_date` balance sheets reuse the period sheet. Comparison uses the same scope. Unknown scope is 400.
- `lookup_audit_events` and `GET /audit-events` list existing `accounting_integration.outbox_event` rows for the bound tenant, including already-published rows (`outbox_event_id`, `event_type_code`, `aggregate_reference`, `payload_reference`, `payload_hash`, `created_at`, plus `published_at` so auditors see drain state). Optional `event_type_code` is `posting_receipt`, `period_close`, or `journal_reversal`; omit it to return all types and omit that document key. Default `page_limit` is 50, maximum 100, and `next_cursor` reuses `created_at|outbox_event_id`. Empty history returns `audit_events` []. The read never sets `published_at`. `GET /outbox-events` remains unpublished-only. `POST /audit-events` is 405.
- `lookup_legal_entities` and `GET /legal-entities` list existing `legal_entity_record` rows for the bound tenant (`legal_entity_reference` from `legal_entity_code`, plus stored `entity_name`). Empty tenants return `legal_entities` []. The catalog is small, so the list is not paged. `POST /legal-entities` is 405.
- `GET /financial-statements` accepts optional `comparison_fiscal_period_reference` on the existing route. When omitted, the document keeps today's keys. When present, the same `statement_type_code` is projected for that prior period as `comparison_statement_lines`, `comparison_total_debit_amount`, `comparison_total_credit_amount`, and `comparison_net_income_amount`. Unknown comparison periods are 404; cross-tenant is 403.
- Hard-close on `POST /period-closes` posts one AIS-owned closing journal that zeros revenue and expense into catalog `retained_earnings` → `310100` (equity, credit-normal) before the trial-balance snapshot. Soft-close writes zero closing journals. Re-hard-close does not post a second closing journal. `GET /financial-statements` income statement excludes those closing journals so `net_income_amount` matches pre-close earnings; the hard-closed balance sheet includes `310100` and returns `net_income_amount` `0`. Ordinary Billing proposals cannot use `retained_earnings`.
- `POST /period-closes` accepts optional body `period_status_code` (`soft_closed` | `hard_closed`; omit still `hard_closed`). Soft-close sets the period, rejects ordinary posts, allows append-only reversal, writes no trial-balance snapshot, and keeps `GET /trial-balances` live. Hard-close snapshots once (including after soft-close) and rejects posts and reversals. Re-soft-close is idempotent. `hard_closed` → `soft_closed` is 422 and writes zero rows. The close receipt keeps existing keys and includes `period_status_code`.
- `lookup_accounting_books` and `GET /accounting-books?legal_entity_reference=` list existing `accounting_book` rows for one tenant entity (`accounting_book_reference` / `book_reference` from `book_name`, `intended_book_role_code` from `book_role_code`, and `book_name`). Empty entities return `accounting_books` []. The catalog is small, so the list is not paged. `POST /accounting-books` is 405.
- `lookup_financial_statement` and `GET /financial-statements?legal_entity_reference=&book_reference=&fiscal_period_reference=&statement_type_code=` project an `income_statement` or `balance_sheet` from the same trial-balance totals as `GET /trial-balances`. Lines reuse TB `chart_account_code`, `debit_amount`, and `credit_amount`, plus catalog `account_role_code` and `account_class_code`. `net_income_amount` is credit-normal earnings on both statements. Empty books return `statement_lines` [] and zero totals. `POST /financial-statements` is 405.
- `database/migrations/0002_chart_account_class.sql` adds durable `account_class_code` (`asset` | `liability` | `equity` | `revenue` | `expense`) on `chart_account`. Seeded 110100 and 110200 are `asset`, 210100 is `liability`, and 410100 is `revenue`.
- `lookup_chart_accounts` and `GET /chart-accounts?legal_entity_reference=&book_reference=` return existing `chart_account` rows (`chart_account_code`, `account_name`, `normal_balance_code`, `account_class_code`) for one tenant entity and book. Empty books return `chart_accounts` []. `POST /chart-accounts` is 405.
- `lookup_account_ledger` and `GET /account-ledgers?legal_entity_reference=&chart_account_code=` return posted `journal_entry_line` rows for one statutory chart account (`line_number`, `chart_account_code`, `account_role_code`, `debit_amount`, `credit_amount`, plus `journal_reference` and `posted_at`). Optional `fiscal_period_reference` scopes the lines. `period_debit_total` and `period_credit_total` are exact decimals for the full filtered scope. Default `page_limit` is 50, maximum 100, and `next_cursor` is `posted_at|journal_reference|line_number`. Empty activity returns `ledger_lines` [].
- `lookup_fiscal_periods` and `GET /fiscal-periods?legal_entity_reference=` list existing `fiscal_period` rows for one tenant entity (`fiscal_period_reference`, `period_code`, `period_start_date`, `period_end_date`, `period_status_code`); default `page_limit` is 50, maximum 100, and `next_cursor` is `period_start_date|period_code`. Empty calendars return `fiscal_periods` []. Single GET by `fiscal_period_reference` and `POST /fiscal-periods` are unchanged.
- `lookup_outbox_events` and `GET /outbox-events?event_type_code=` list unpublished `accounting_integration.outbox_event` rows for one tenant (`outbox_event_id`, `event_type_code`, `aggregate_reference`, `payload_reference`, `payload_hash`, `created_at`); default `page_limit` is 50, maximum 100, and `next_cursor` is `created_at|outbox_event_id`. Empty unpublished sets return `outbox_events` []. `publish_outbox_event` and `POST /outbox-events/{outbox_event_id}/publish` set `published_at` on that tenant row; replay is idempotent. Persist writes `posting_receipt`, `journal_reversal`, and `period_close` in the same transaction as post, reverse, and close. `GET /posting-receipts` is unchanged.
- `lookup_period_journals` and `GET /journals?legal_entity_reference=&fiscal_period_reference=&book_reference=` list existing posted and reversing `general_journal` rows for one tenant period (`journal_reference`, `idempotency_key`, `journal_status_code`, `accounting_date`, `line_count`); default `page_limit` is 50, maximum 100, and `next_cursor` is `accounting_date|journal_reference`. Empty periods return `journals` []. Single-journal GET by key or reference is unchanged.
- Billing #20 taxed `credit_adjustment` proposals post the exact three-line Billing split (debit `usage_revenue` 410100, debit `tax_payable` 210100, credit `accounts_receivable` 110100) on the existing `{tenant}:credit_adjustment:{credit_adjustment_id}:{source_payload_hash}:v{version}` key; AIS does not recompute `credit_tax_amount` and does not add `tax_receivable`.

- `accept_period_open`, `lookup_fiscal_period`, `POST /fiscal-periods`, and `GET /fiscal-periods` open the next `fiscal_period` row (or replay an already-open period) and read existing period status and dates; hard-closed and soft-closed periods cannot be reopened.
- `lookup_posted_journal` and `GET /journals` return the persisted posted journal and its lines (`chart_account_code`, exact decimal debit/credit, `line_number`) by Billing `idempotency_key` or `journal_reference`; a reversing journal is returned when that identity is a reversal, and missing journals fail closed. `POST /journals` is the AIS adjusting-journal write.
- `lookup_account_role_mappings` and `GET /account-role-mappings` return the existing catalog `account_role_code` → `chart_account_code` rows plus stored policy and posting-rule versions for one tenant, legal entity, and book; missing catalog fails closed and `POST /account-role-mappings` is 405.

- `accept_journal_reversal` and `POST /journal-reversals` append an equal-and-opposite reversing journal through existing `PostgresPostingLedger.reverse` and return the reversing `accounting_posting_receipt`; the original receipt lookup is unchanged.
- `pull_validated_journal_proposals`, `pull_journal_proposal`, `accept_pulled_proposals`, `accept_billing_proposal_pull`, and `POST /billing-proposal-pulls` pull Billing #15 `validated` journal-proposal pages (`journal_proposals` + `next_cursor`) and post them without flipping Billing `proposal_status`.
- `accept_period_close`, `lookup_trial_balance`, `POST /period-closes`, and `GET /trial-balances` close a fiscal period and read snapshot or live trial-balance totals over the same purpose-limited HTTP surface; `GET /healthz` is an ops probe.
- `lookup_published_receipt` and `GET /posting-receipts` return the persisted `accounting_posting_receipt` for a purpose-limited tenant and Billing idempotency key without inventing a missing receipt.
- Catalog `account_role_mapping` for `cash_receipt` so a Billing `validated` cash proposal posts debit cash / credit accounts receivable through `post_proposal`.
- `accept_journal_proposal` and a stdlib `POST /journal-proposals` boundary that return the AIS posting-receipt contract, scoped by purpose-limited `X-CWL-Tenant-Reference`.
